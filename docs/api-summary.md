# /api/summary のつなぎ方

問診の回答を送ると、Gemini が作った要約と食い違いが返ってきます。AI は診断しません。

この説明は `gemini-a` ブランチの `c58e41e` のコードで確かめました。「拒否される」と書いた項目と例は、ローカルのサーバーに実際に送って確かめたものです。

## 送り先と送り方

| 項目 | 内容 |
|---|---|
| 送り先 | `/api/summary` |
| 送り方 | `POST`（`GET` は 405） |
| 形式 | JSON（`Content-Type: application/json`） |
| 認証 | 画面側では不要。API キーも使わない |
| 全体の大きさ | 20,000 文字まで（超えると 413） |

**新しい画面は、同じ Next.js アプリの中に作ってください。** 別の場所（別のドメインやポート）の画面から呼ぶための設定（CORS）はないので、ブラウザが止めます。

## 送るデータの形

`patient`（本人）と `family`（保護者）の2つを入れた JSON を送ります。

- `patient` と `family` は、**どちらも必ず入れます。** 回答がない側は `{}` にします。
- **中の項目はすべて任意です。** ただし、両方とも空だと 400 になります。
- 回答がない項目は、キーごと入れません。`null`、`""`、`[]` は 400 になります。
- 値は下の一覧と**1文字も違わない形**にします。

### patient（本人）

| 項目 | 画面の質問 | 型 | 選べる値 |
|---|---|---|---|
| `bodyParts` | どこが へん？ | 文字の配列（1つ以上、重複なし） | `頭` `耳` `のど` `胸` `お腹` `手・足` `その他` |
| `feelings` | どんな かんじ？ | 文字の配列（1つ以上、重複なし） | `いたい` `きもちわるい` `だるい` `いきが くるしい` `せきが でる` `ねつっぽい` |
| `discomfort` | どれくらい つらい？ | 文字 | `へいき（5段階の1）` `すこし つらい（5段階の2）` `つらい（5段階の3）` `とても つらい（5段階の4）` `すごく つらい（5段階の5）` |

### family（保護者）

| 項目 | 画面の質問 | 型 | 選べる値 |
|---|---|---|---|
| `chiefConcern` | 一番心配なこと | 文字 | 自由入力。**500 文字まで**。空白だけは不可 |
| `onset` | いつからですか？ | 文字 | `今日` `昨日` `2〜3日前` `1週間くらい前` `それより前` |
| `temperature` | 熱 | 文字 | `38.5 ℃` の形、または `測っていない` |
| `foodIntake` | 食べる・飲む | 文字 | `いつもどおり` `少ない` `ほとんどない` |

### 間違えやすいところ

- **空白:** `いきが くるしい`、`せきが でる`、`すこし つらい` などの空白は半角です。
- **`bodyParts`:** 画面に「おなか」と出していても、送る値は `お腹` です。`おなか` は 400 になります。
- **`feelings`:** `そのほか・わからない` は送れません。**配列から取り除きます。** 残りが空になったら、`feelings` ごと入れません。
- **`discomfort`:** 数字（`3`）や `つらい` だけでは 400 になります。
- **`onset`:** `わからない` は送れません。`onset` ごと入れません。
- **`temperature`:** 数字（`38.5`）、`38.5`、`38.5℃`（空白なし）は 400 になります。数字と ℃ の間に半角の空白を入れます。小数は1桁までです。
- **体温の値の大きさ:** サーバーは見ません。おかしな値を防ぐなら、画面側で確かめます。
- **文字数:** 500 文字を超えると 400 になります。送る前に画面側で確かめ、超えたら送らないでください。文字数は `[...text].length` で数えます。

## 送ってはいけない項目

次の項目は Gemini に送りません。**入っていると、全体が 400 で拒否され、要約は作られません。**

- 飲んでいる薬、アレルギー、持病
- 年齢、体重、身長、性別、名前

一覧にない項目は、どんな名前でも拒否されます。`patient`、`family`、一番外のどこに入れても同じです。薬とアレルギーを医師に見せるときは、Gemini を通さず、画面側で入力どおりに出します。

**サーバーが見るのは項目の名前と値の形だけです。** `chiefConcern` の文の中に名前や薬が書かれていても、拒否できず、そのまま Gemini に送られます。

## 返ってくるデータの形

成功すると、200 で次の形が返ります。

| 項目 | 型 | 内容 |
|---|---|---|
| `ok` | 真偽値 | `true` |
| `summary.patientSummary` | 文字 | 本人の回答の要約 |
| `summary.familySummary` | 文字 | 保護者の回答の要約 |
| `summary.discrepancies` | 配列 | 本人と保護者の食い違い（なければ `[]`） |
| `summary.discrepancies[].topic` | 文字 | 何についての食い違いか |
| `summary.discrepancies[].patient` | 文字 | 本人の答え |
| `summary.discrepancies[].family` | 文字 | 保護者の答え |

- **回答がない側:** その側の要約は `""`、`discrepancies` は `[]` になります。この場合は比べていないので、「食い違いなし」と出さないでください。今の画面は「食い違い：比べていません（片方の回答がありません）」と出しています。
- **文面:** 同じ入力でも、言い回しや文の形は毎回変わります。文面に頼った処理はしないでください。
- **`discrepancies` が `[]` のとき:** 「AI が見つけなかった」という意味で、食い違いがないことの保証ではありません。

## 失敗のときの返り方

失敗のときの中身はどれも `{"ok":false}` で、理由は入っていません。

| 状態 | 意味 | 画面側ですること |
|---|---|---|
| 400 | データの形が違う、項目が多い、両方とも空 | 作るときの誤りなので、送るデータを直す |
| 413 | 全体が 20,000 文字を超えた | 送るデータを直す |
| 502 | Gemini で失敗した（時間切れ、混雑など） | 「もう一度試す」を出す |

コードにはもう1つ 499 があります。ブラウザが接続を切ったあとの返事なので、画面側には届きません。

### 待つ時間

- **画面側: 50 秒待ちます。** 過ぎたら通信を中止し、失敗として扱います。
- **サーバー側:** 1回 15 秒で打ち切り、最大2回やり直します（全体で 45 秒まで）。
- ふだんは 3〜10 秒ほどですが、やり直しが入ると 30 秒ほどかかることがあります。50 秒より短くしないでください。
- 待っている間に別の画面へ移ったら、通信を中止します。古い回答の要約を出さないためです。

失敗したときは、「要約を作れませんでした」と伝え、元の回答を見られるようにしてください。

```ts
const controller = new AbortController();
const timer = setTimeout(() => controller.abort(), 50_000);

try {
  const response = await fetch("/api/summary", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(input),
    signal: controller.signal,
  });
  if (!response.ok) {
    // 失敗の表示と「もう一度試す」を出す
    return;
  }
  const body = await response.json();
  // body.summary を使う
} catch {
  // 時間切れ、または通信の失敗。失敗の表示と「もう一度試す」を出す
} finally {
  clearTimeout(timer);
}
```

## 例（架空のデータ）

### 送るデータ

```json
{
  "patient": {
    "bodyParts": ["お腹"],
    "feelings": ["いたい"],
    "discomfort": "つらい（5段階の3）"
  },
  "family": {
    "chiefConcern": "頭をおさえている",
    "onset": "今日",
    "temperature": "測っていない",
    "foodIntake": "少ない"
  }
}
```

### 返ってくるデータ

上のデータを実際に送ったときの結果です。

```json
{
  "ok": true,
  "summary": {
    "patientSummary": "へんなところ：お腹。どんなかんじ：いたい。つらさ：つらい（5段階の3）。",
    "familySummary": "今いちばん心配な症状：頭をおさえている。今日から。体温：測っていない。食事・水分：少ない。",
    "discrepancies": [
      {
        "topic": "症状の部位",
        "patient": "お腹",
        "family": "頭をおさえている"
      }
    ]
  }
}
```

## 画面を作るときに守ること

- **本人と保護者を混ぜません。** 要約も食い違いも、分けて出します。保護者が本人の答えを書き換えられるようにもしません。
- **AI の表示を残します。** 要約には「AIの整理です。診断ではありません。」、食い違いには「AIが見つけたもの」と出します。
- **データは保存しません。** データベース、`localStorage`、`sessionStorage` に入れません。
- **ログに出しません。** 回答や要約を `console.log` などに出しません。
- **推測で埋めません。** 答えのない項目は、キーごと送りません。
